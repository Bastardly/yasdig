Intro to models

A model is what draws the picture. It is a big file of learned numbers — 2 to 20 GB — and each one has its own look and its own idea of good settings. The Models tab downloads a working set for each kind this app runs, so this page is for when you want to know what you are looking at, or go looking for more.

One file, or several

An SDXL or SD 1.5 checkpoint is one file with everything inside. Drop it in models/checkpoints and pick it.

The newer models — Flux, Klein, FLUX.3, Z-Image, Krea 2, Qwen-Image — come as a diffusion model plus separate parts:

PartWhat it does
Text encoderReads your prompt and turns it into something the model understands. Often a whole language model (Qwen3, T5), and often as large as the model itself.
VAETurns the model’s compressed result into pixels at the end. Small, but it has to be the right one: the wrong VAE gives coloured noise.

The parts must match the model exactly. A text encoder of the wrong size loads without complaint and quietly ignores your prompt. yasdig reads every file to find out what it is, so file names and folders don’t matter — but it can only pick from what you have. Each model’s parts are in the Models fold on the Image tab.

What each family needs

The Models page lists the families and what each takes on the card; in the app, the Models tab shows each family's parts, the recommended set and which files you already have.

File types

EndingWhat it is
.safetensorsThe usual format. Often full precision (fp16 or bf16) — the largest version of a model.
.ggufA packed format that can be quantized: stored in fewer bits, so smaller and lighter on memory.
.ckpt, .pt, .pthOlder formats. Fine for upscalers; prefer .safetensors for anything else.

Quantization is the Q8_0, Q6_K, Q4_K in a GGUF’s name: the bits per number. Q8 looks the same as the original at half the size. Q6 and Q5 are very close. Q4 is about a quarter of the size and starts to lose fine detail — the way to fit a 20B model on one card.

Avoid fp8 files on this app. AMD cards can’t compute in fp8, so an fp8 file runs at twice its size. Models → Convert turns one into a GGUF that runs at its real size.

Where to find more

Hugging Face (huggingface.co) is where models are published: the original releases, and GGUF versions by people like city96, leejet, unsloth and QuantStack. A repository holds many files; open its Files tab and download one — the quantization that fits your card — not the whole thing. Some repositories ask you to log in and accept a licence first.

Civitai (civitai.com) is the community’s shelf: thousands of fine-tuned checkpoints and LoRAs, mostly SDXL, Pony, Illustrious and SD 1.5. Check the Base model on a page before downloading. Some downloads need a free account.

Check the licence. Every model, checkpoint and LoRA comes with its own terms, and they differ a lot: some allow anything, some forbid commercial use of the images, some are for research only, and some ask you to accept terms before downloading. The licence is on the model’s page (on Hugging Face, in the model card and the License tag; on Civitai, under the model’s permissions). A quantized copy — a GGUF someone else made — is still under the original model’s licence. That includes the files the Models tab downloads; each card links their pages.

A LoRA is a small add-on (10–300 MB) that teaches a model a style, a character or a detail. It only works on the family it was trained for — an SDXL LoRA does nothing on Flux — and the LoRA picker greys out the ones that don’t fit. They go in models/loras.

Where files go

FolderWhat goes in it
models/checkpointsOne-file models: SDXL, SD 1.5, and their fine-tunes
models/diffusion_modelsDiffusion models that need parts: Flux, Klein, FLUX.3, Z-Image, Krea 2, Qwen-Image, MOSS-Image, Iris, MiniMax H3 Image
models/text_encodersText encoders: Qwen, T5, CLIP-L
models/vaeVAEs
models/lorasLoRAs
models/upscalersUpscaler models (ESRGAN, SPAN, SwinIR…)

These are the folders ComfyUI uses, so its download instructions work here. They are for you: yasdig reads every file under models/, so a model is found wherever it is — except that LoRAs and upscalers must be in their own folders.
