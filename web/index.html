Clips

What this is for

A file's type on disk is not what it costs to run. When the backend can't multiply the stored type — every Vulkan device today reports no fp8 — sd.cpp casts each layer's weights at run time instead, so an fp8 checkpoint executes as if it were BF16 and needs about twice its own size. Converting to a type the backend multiplies natively is smaller and faster.

The result is written beside its source, so it is discovered on the next start with no config edit. Nothing is deleted — the original stays where it is.

A variable is a name and a list of words. Name one animal, give it crab, horse, dog, and {animal} anywhere in a prompt becomes one of them — a different one per image, so Generate 20 is twenty subjects rather than twenty seeds of one picture. Braces rather than [brackets] because [cat] already means something to the sampler: it de-emphasises the word. Case is ignored, and a name nothing answers to is reported rather than quietly drawn into the image as text.

What these are

A model starts from four layers, each overriding the one before it only where it says something: the form on the left (user/settings.toml); its family's defaults, which set size, steps, CFG and sampler for every family but SD and SDXL; a [templates.<name>] block in models.toml, if you wrote one; and Per model above (user/model-settings.toml).

Both files here are rewritten in full on every save, and Per model keeps only what differs from where the model would start anyway — so raising a setting on the left still reaches every model that has no opinion of its own about it.

Nothing here is retroactive: an image already made keeps the settings it was made with, which is what lets reopening a work item restore it faithfully.
